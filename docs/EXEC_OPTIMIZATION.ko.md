# Python을 유지한 단일 exec 최적화

한국어 | [English](EXEC_OPTIMIZATION.md)

`codex/external-host-compiler`의 **v0.3.0-rc.2에 포함하는 변경**입니다. CLI와 호스트는
Python, C# 컴파일러는 기존 Roslyn을 유지합니다. 아래 측정은 RC2 버전 변경 전에
수행했으며 원자료는 당시 개발 버전 `0.3.0-rc.1`과 해시를 그대로 보존합니다.

## 변경과 비교 기준

호환 호스트가 이미 실행 중이면 짧게 실행되는 CLI에서 전체 parser·client·adapter를
로드하지 않고 요청을 상주 Python 호스트에 전달합니다. 호스트는 기존 parser, 출력,
프로젝트 탐색과 순차 실행 대기열을 사용합니다. 고정 루프백 주소의 연결에는 불필요한
호스트 이름 처리를 생략합니다. 기존 명령 형식, Python API, C# 컴파일과 실제 Unity
실행은 유지합니다. Standalone 표준 입출력은 UTF-8로 맞춰 Windows 파이프에서 한글과
이모지를 처리합니다.

기준은 공개 RC1이 아니라 **이번 변경 직전의 작업 브랜치 실행 파일**입니다.
[앞선 개선](SPEED_FOLLOWUP.ko.md)의 지연 로딩, ReadyToRun, 공유 참조 캐시, JSONL
세션을 이미 포함합니다. 두 묶음의 컴파일러 파일 220개는 SHA-256이 모두 같고,
Connector도 동일한 작업 폴더 소스를 복사했습니다. 따라서 앞선 컴파일러 개선을
이번 Python 경로의 이득으로 중복 계산하지 않습니다.

## 준비된 호출의 실측

2026-09-18, Windows 11, Python 3.14.4 / PyInstaller 6.20.0입니다.
Unity 버전마다 빈 프로젝트에서 이전→개선→개선→이전 순서로 실행했습니다.
각 명령과 각 exec 종류는 변형별 80회이며, 별도 CLI 프로세스 시작부터 결과 수신까지
측정했습니다. 호스트와 컴파일러 사전 준비 이후의 값입니다. 단위는 ms,
백분위는 nearest-rank입니다.

| Unity | 실행 종류 | 이전 p50 / p95 | 개선 p50 / p95 | p50 감소 |
|---|---|---:|---:|---:|
| 2021.3.19f1 | 서로 다른 코드 | 109.9 / 140.4 | 91.4 / 110.5 | 16.8% |
| 2021.3.19f1 | 같은 코드 반복 | 109.0 / 141.7 | 78.6 / 109.9 | 27.9% |
| 6000.3.13f1 | 서로 다른 코드 | 122.4 / 141.0 | 93.1 / 110.5 | 24.0% |
| 6000.3.13f1 | 같은 코드 반복 | 111.8 / 141.7 | 93.0 / 111.1 | 16.8% |

exec p95는 약 30~32ms, 21~23% 감소했습니다. 복잡한 C# 코드 자체나 Unity 작업이
같은 비율로 빨라진다는 뜻은 아닙니다. 실행마다 컴파일 결과를 새 assembly identity로
emit하고 실제 코드를 다시 실행합니다. 결과나 정적 상태는 재사용하지 않습니다.

| 일반 명령 | Unity 2021: 이전 → 개선 p95 | Unity 6: 이전 → 개선 p95 |
|---|---:|---:|
| status | 70.6 → 73.2 | 71.7 → 72.1 |
| console | 124.4 → 118.9 | 120.2 → 119.1 |
| tools | 125.1 → 125.3 | 119.5 → 125.2 |

두 버전 모두 `기존 p95의 5% 또는 10ms 중 큰 값`의 저하 한도를 통과했습니다.
모든 명령이 빨라졌다는 의미는 아닙니다. 초기 10회 예비 측정에서는 tools가 한도를
넘었고, 해당 결과도 보존했습니다. 위 표는 최종 실행 파일의 더 큰 교차 표본입니다.

## 첫 실행과 비용

| Unity | 서비스 시작부터 첫 결과: 이전 → 개선 | 사전 준비만 끝낸 첫 exec: 이전 → 개선 |
|---|---:|---:|
| 2021.3.19f1 | 500.2–504.2 → 506.0–509.8 | 115.6–116.1 → 88.9–102.5 |
| 6000.3.13f1 | 557.5–559.0 → 578.2–581.2 | 110.3–111.2 → 91.7–113.7 |

첫 실행은 각각 2회이므로 백분위 대신 범위로 표시합니다. **서비스까지 처음 켜는
경우의 개선은 확인되지 않았습니다.** 서비스·컴파일러를 새로 시작했지만 OS 파일
캐시는 비우지 않았으며, 설치 직후나 재부팅 직후의 측정은 아닙니다.

설치 용량은 129.24 → 129.26 MiB로 약 22 KiB 증가했습니다. 호스트 working set은
Unity 2021에서 33.92 → 34.05–34.57 MiB, Unity 6에서 33.54–34.18 →
34.39–34.50 MiB였습니다. 각 변형에서 두 번 읽은 값이며 최대 메모리 측정이 아닙니다.
새 언어 런타임이나 컴파일러 파일은 추가하지 않았습니다.

exec 중 1ms보다 긴 Editor update 간격의 p95는 Unity 2021에서 5.68 → 6.24ms,
Unity 6에서 5.34 → 5.18ms였습니다. 최댓값은 각각 6.46 → 12.75ms,
6.64 → 12.88ms로 늘었습니다. batchmode/nographics의 관찰값으로, GUI 끊김이나
프레임 개선을 주장할 근거는 아닙니다.

## 안전성과 검증

- 인증, 실행 순서, 원래 제한 시간, Unity 실행 잠금 이후의 만료 확인을 유지합니다.
- 경량 경로를 쓸 수 없으면 전송 전에 기존 CLI를 사용합니다. 전송을 시도한 뒤
  응답이 유실되면 `unknown`을 표시하며 다른 경로로 재실행하지 않습니다.
- 자동 업데이트 코드·주기·네트워크 동작은 유지했습니다. 확인 시기가 된 일반 텍스트
  호출은 기존 CLI가 처리합니다. 측정은 양쪽 모두 업데이트 확인을 생략했습니다.
- Python 196개 중 195개 통과, Windows 심볼릭 링크 권한으로 1개 생략했습니다.
  POSIX 설치 테스트는 접근 가능한 작업 폴더의 임시 경로에서 통과했습니다.
- 경량 경로 14개는 소스, Windows 실행 파일, ZIP을 새 경로에 푼 실행 파일에서 각각 통과했습니다. 파일·stdin·
  Unicode·인증·만료·응답 유실·동시 요청 출력·구버전 호환·업데이트 주기를 포함합니다.
- 실제 Unity 2021과 6에서 각각 18/18을 통과했습니다. 정적 상태 격리, 컴파일 오류
  복구, 참조 변경, 리로드, 만료 후 부작용 방지를 확인했습니다.
- 5개 플랫폼 CI에 압축을 푼 실행 파일의 경량 경로 검증을 추가했습니다.
  이번 작업에서 Linux/macOS CI 실행이나 릴리즈는 수행하지 않았습니다.

대형 프로젝트, GUI·백그라운드 창, 재부팅 직후, 장시간 assembly 누적, 에이전트 요청부터
화면 응답까지의 시간과 토큰 사용량은 이번 측정 범위가 아닙니다.

[원자료·판정·소스 및 실행 파일 해시](EXEC_OPTIMIZATION_BENCHMARK.json)를 함께 보존합니다.
재현 시 `scripts/benchmark-host.py`에 두 실행 파일과 `--baseline-host
--baseline-working-tree-connector --baseline-ref 5945c3b --samples 40 --exec-samples 40`을
지정합니다. 진단용 `UNITY_BRIDGE_DISABLE_FAST_EXEC=1`은 현재 실행 파일에서 경량
경로를 끕니다. 빌드·기능 검증은 [개발 안내](DEVELOPMENT.ko.md)를 참고하세요.
