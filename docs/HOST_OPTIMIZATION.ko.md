# 독립 호스트 추가 최적화 검증 — 2026-09-17

수정 전 `1749359`과 수정 후 `5a49f00`을 비교했습니다. 둘 다 `codex/external-host-compiler`의 미출시 `0.3.0-alpha.1`입니다. 이번 수치는 개발 브랜치 내 개선 효과이며, v0.2.3 비교는 [기존 보고서](HOST_VALIDATION.ko.md)에 보존했습니다. main과 릴리즈 태그는 변경하지 않았습니다.

## 변경 내용과 유지한 동작

- HTTP 수신·읽기·쓰기가 Unity 업데이트 루프를 다시 기다리지 않게 했습니다. 도구 호출과 결과 직렬화, Unity API를 사용하는 결과 getter는 메인 스레드에 유지했습니다. Connector의 dispatch await도 Unity 동기화 컨텍스트를 유지합니다.
- 요청에 수신 리스너의 취소 토큰을 연결하고 dispatch 전과 실행 잠금을 얻은 뒤에 확인합니다. 리스너 중지·교체 후 이전 연결에서 기다리던 변경 명령이 실행되지 않습니다. 이미 실행 중인 사용자 코드를 강제로 중단하지는 않습니다.
- `PreparedContext`에서 프로젝트 경로와 참조 해시를 협상 시 한 번 준비합니다. 도메인·참조 변경 시 교체하며, 기존 프로젝트 스캔 때 사용하지 않을 큐·조건변수도 새로 만들지 않습니다.
- `MetadataReferenceCache`에 참조 읽기·MVID 검증을, `BoundedCache`에 보관 한도 관리를 분리했습니다. 처음 읽은 이미지 하나를 검증과 Roslyn에 함께 사용합니다. 캐시가 있어도 실제 DLL MVID를 매번 확인하며, 실행 결과·정적 상태·로드된 Assembly를 재사용하지 않습니다.
- 이미 시작된 워커 제한 시간 콜백이 끝난 뒤 잠금을 풀도록 했습니다. 이전 코드의 경쟁 상태를 재현하는 회귀 테스트를 추가했습니다.
- 기존 직접 연결도 로컬 HTTP 연결 하나를 사용해 불필요한 HTTPS·인증서 준비를 생략합니다. 성공·오류·일반 문자열·빈 응답 의미를 유지합니다. 환경 프록시·리다이렉트는 따르지 않으며, 응답 유실 후 명령을 재실행하지 않습니다.

## 검증

- 로컬 Python: 167개 중 166개 통과, 기존 Windows 심볼릭 링크 권한 테스트 1개 건너뜀. 실제 Roslyn: 13/13 통과.
- 설치용 실행 파일 + Unity 2021.3.19f1·6000.3.13f1: 각각 14/14 통과. 비동기 도구·결과 getter의 메인 스레드 접근, 잠금 대기 중 리스너 재시작, 오래된 호스트 PID 복구, 리로드, 정적 상태 격리, 참조 변경, 제한 시간, 상태 조회, 컴파일 오류 복구, 재생·일시정지를 확인했습니다.
- 실제 Windows 묶음의 신규 설치와 v0.2.3 업그레이드 통과. 격리한 사용자 지정 경로에서 번들 워커 실행·이전 런타임 보존·사용자 PATH 유지까지 확인했습니다.
- `5a49f00`의 [5개 플랫폼 CI 빌드·회귀 검증 통과](https://github.com/zjxps2007/UnityBridge/actions/runs/35123845115). Windows x64, Linux x64·ARM64, macOS Intel·Apple Silicon이며 릴리즈 게시는 건너뛰었습니다.

## 같은 조건의 전체 명령 응답 시간

Windows 11에서 두 실행 파일 모두 Python 3.14.4·PyInstaller 6.22.3으로 빌드했습니다. 양쪽 모두 호스트 경로를 사용하고, 빈 Unity 프로젝트에서 수정 전→후→후→전 순서로 실행했습니다. 일반 명령은 버전·구현별 80회, 새 코드·같은 코드 실행은 각각 40회입니다. 단위는 ms이며 p50·p95는 nearest-rank 방식입니다. CLI 프로세스 시작부터 JSON 응답 완료까지 측정했습니다. 전용 장비·CPU 고정 환경이 아닌 데스크톱의 batchmode 결과로, GUI 프레임이나 사용자 질문부터 답변까지의 시간은 아닙니다. 표의 Before/After는 수정 전/후입니다.

| Unity | Command | Before p50 / p95 (ms) | After p50 / p95 (ms) |
|---|---|---:|---:|
| 6000.3.13f1 | `status` | 83.5 / 85.9 | 82.7 / 86.8 |
| 6000.3.13f1 | `console` | 217.0 / 266.6 | 104.7 / 121.4 |
| 6000.3.13f1 | `tools` | 250.0 / 250.9 | 109.1 / 125.4 |
| 6000.3.13f1 | `unique_exec` | 249.9 / 251.4 | 124.0 / 139.0 |
| 6000.3.13f1 | `repeat_exec` | 250.2 / 251.2 | 124.5 / 142.3 |
| 2021.3.19f1 | `status` | 84.0 / 90.7 | 83.4 / 91.0 |
| 2021.3.19f1 | `console` | 216.3 / 264.8 | 104.6 / 119.5 |
| 2021.3.19f1 | `tools` | 250.2 / 251.7 | 109.1 / 124.9 |
| 2021.3.19f1 | `unique_exec` | 249.9 / 250.9 | 121.8 / 143.0 |
| 2021.3.19f1 | `repeat_exec` | 250.0 / 251.3 | 110.2 / 125.9 |

일반 명령 p95의 6개 기준을 모두 통과했습니다. 허용 증가량은 `기준의 5% 또는 10ms 중 큰 값`입니다. `status`는 로컬 파일 조회·프로세스 시작 비용이 주를 이루므로 큰 속도 개선을 주장하지 않습니다.

## 첫 응답과 자원 사용

각 항목은 2회뿐이므로 백분위 대신 범위를 제시합니다. 완전한 첫 응답은 Unity 준비 후 호스트 시작·참조 협상·첫 사용자 결과를 포함합니다. 설치·Unity 시작·재부팅·디스크 캐시 초기화는 포함하지 않습니다. Prewarm-only는 워커를 재시작해 자동 참조 준비만 마친 뒤 처음 실행한 사용자 코드입니다.

| Unity | Cold before / after (ms) | Prewarm-only first exec before / after (ms) |
|---|---:|---:|
| 6000.3.13f1 | 1060–1651 / 827–847 | 239–276 / 136–142 |
| 2021.3.19f1 | 1021–1029 / 758–769 | 253–285 / 112–125 |

| Unity | Exec max Editor gap before / after (ms) | Host RSS before / after (MiB) | Worker RSS before / after (MiB) |
|---|---:|---:|---:|
| 6000.3.13f1 | 8.4 / 6.1 | 33.3–33.4 / 32.4–32.8 | 219.8–220.0 / 207.9–208.6 |
| 2021.3.19f1 | 6.5 / 6.9 | 32.9–33.0 / 32.1–32.5 | 207.7–207.9 / 179.0–179.3 |

Editor gap은 전체 exec 구간에서 1ms를 초과한 업데이트 간격입니다. GUI 프레임 시간이 아닙니다. RSS는 실행 후 상주 메모리 범위이며 최대치·전용 메모리가 아닙니다. 프로젝트와 참조 수에 따라 달라집니다. Windows 압축 해제 크기는 113.2→113.2 MiB, 수정 후 ZIP은 50.1 MiB입니다.

별도 참조 로더 측정은 .NET 참조 DLL 174개·63.2 MiB, 빈 메타데이터 캐시·준비된 OS 파일 캐시에서 구현별 20회 교차 실행했습니다. 중앙값은 28.19→17.69ms, 해당 스레드의 메모리 할당량은 191.87→127.37 MiB였습니다. 컴파일·Unity 실행을 제외한 부분 측정이므로 위 전체 응답 개선량에 더할 수 없습니다.

## 범위와 재현

실제 Unity 실행은 Windows의 위 두 Editor를 확인했습니다. Linux·macOS는 CI 검증이며 실제 Unity 실행 측정은 아닙니다. Unity 2020.3도 소스·API 호환성 근거만 있습니다. 모든 프로젝트·OS·창 포커스 상태·차가운 디스크 캐시에 같은 개선을 보장하지 않습니다. 프로젝트 소스 변경에는 여전히 Unity 컴파일·리로드가 필요합니다.

[검증 실행 안내](../tests/unity/README.md)에 따라 이전 실행 파일을 보관하고 `scripts/benchmark-host.py`에 `--baseline-host --baseline-ref 1749359`을 추가해 재현합니다. [기계 판독용 근거](HOST_OPTIMIZATION_BENCHMARK.json)에 전체 표본·기준·자원 사용·네이티브 검증·묶음 해시를 보존했습니다. 상세 로컬 로그는 `.codex-deps/host-optimization/`에 있습니다.
