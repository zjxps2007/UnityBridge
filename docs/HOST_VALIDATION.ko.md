# 독립 서비스 검증 결과 — 2026-09-17

`v0.2.3` 정식 배포를 완료한 뒤 `codex/external-host-compiler`에서 `0.3.0-alpha.1`을 구현했습니다. 새 구조는 메인에 병합하거나 릴리즈하지 않았습니다.

## 실제 응답 시간

같은 Windows PC, Python 3.14.4/PyInstaller 6.22.3 실행 파일, 빈 Unity 프로젝트에서 기준→후보→후보→기준 순서로 비교했습니다. 각 명령은 CLI 프로세스 시작부터 응답 JSON 수신까지 측정했습니다. 일반 명령은 버전별·경로별 80회, 새 코드와 반복 코드 실행은 각각 40회입니다.

| Unity | 명령 | v0.2.3 p50 / p95 | 독립 서비스 p50 / p95 |
|---|---|---:|---:|
| 6000.3.13f1 | `status` | 82.3 / 89.8 ms | 83.1 / 86.9 ms |
| 6000.3.13f1 | `console` | 217.9 / 267.6 ms | 217.1 / 266.3 ms |
| 6000.3.13f1 | `tools` | 250.3 / 251.4 ms | 250.1 / 251.3 ms |
| 6000.3.13f1 | `unique_exec` | 838.3 / 860.3 ms | 250.1 / 251.2 ms |
| 6000.3.13f1 | `repeat_exec` | 838.6 / 849.9 ms | 249.9 / 251.6 ms |
| 2021.3.19f1 | `status` | 82.8 / 87.9 ms | 83.3 / 85.8 ms |
| 2021.3.19f1 | `console` | 217.9 / 268.0 ms | 216.9 / 265.9 ms |
| 2021.3.19f1 | `tools` | 250.3 / 251.3 ms | 250.2 / 251.0 ms |
| 2021.3.19f1 | `unique_exec` | 713.1 / 733.4 ms | 250.0 / 251.1 ms |
| 2021.3.19f1 | `repeat_exec` | 713.2 / 724.9 ms | 249.9 / 251.1 ms |

일반 명령 6개 비교 모두 p95 기준을 통과했습니다. 허용 증가량은 `기준의 5%와 10ms 중 큰 값`입니다. 따라서 호환되는 서비스가 준비된 설치에서는 기본 `auto` 경로를 유지합니다. 서비스가 없거나 구버전 Connector이면 기존 직접 연결을 사용합니다.

## 첫 시작과 사전 준비의 차이

서비스까지 새로 시작하는 호출과, 백그라운드 준비만 마친 새 워커의 첫 사용자 코드를 구분했습니다. 다음은 각 2회 측정 범위이며, 안정적인 백분위 추정치는 아닙니다. Unity 자체 시작·설치 시간은 제외했고 OS 디스크 캐시는 비우지 않았습니다.

| Unity | 서비스 첫 시작 포함: v0.2.3 / 후보 | 사전 준비 후: v0.2.3 / 후보 |
|---|---:|---:|
| 6000.3.13f1 | 935–941 ms / 1068–1114 ms | 840–843 ms / 219–267 ms |
| 2021.3.19f1 | 746–754 ms / 1012–1026 ms | 708–720 ms / 231–249 ms |

완전히 처음 시작할 때에는 외부 서비스와 .NET 워커 준비 비용 때문에 더 느릴 수 있습니다. Unity가 준비된 뒤 자동으로 미리 준비하는 이유입니다. 이 결과를 Codex 요청부터 화면 답변까지의 전체 지연이나 게임 프레임 성능으로 해석하면 안 됩니다.

## 비용과 검증 범위

- Windows 설치 용량: 압축 해제 기준 **20.4 → 113.2 MiB**.
- 메모리와 Editor 업데이트 지연의 정확한 수치는 [상세 보고서](HOST_VALIDATION.md#editor-responsiveness-and-resource-costs)에 있습니다. 메모리는 실행 후 상주 메모리 스냅샷이며 최대치나 순수 추가 메모리와 같지 않습니다.
- 로컬 Python 테스트 155개: 154개 통과, Windows 심볼릭 링크 권한 테스트 1개 건너뜀. 실제 Roslyn 회귀 검증 11개 통과.
- Unity 2021·6 각각 실제 기능 검증 12개 통과. 별도로 공백 포함 경로의 설치 실행 파일로 Unity 6 검증 12개도 통과.
- 두 Unity 프로젝트가 한 서비스를 공유하고, 실제 컴파일러 프로세스 종료 후 다음 요청으로 복구했습니다. Unity를 모두 종료한 뒤 약 30초 후 서비스가 종료됐습니다.
- 실제 Windows 신규 설치와 v0.2.3 업그레이드, 이전 런타임 보존과 설치 실패 롤백을 확인했습니다.
- [5개 플랫폼 CI 모두 성공](https://github.com/zjxps2007/UnityBridge/actions/runs/35120162054). 이 실행은 빌드 산출물만 만들었으며 새 릴리즈를 게시하지 않았습니다.
- Unity 2020.3은 공식 API·소스 호환성을 검토했습니다. 실제 2020 Editor가 없어 실행 검증은 하지 않았습니다. macOS/Linux의 실제 Unity 실행도 이번 Windows 실측에 포함되지 않습니다.
- 매우 긴 Windows 경로는 네이티브 실행 파일·DLL 경로 길이 제한에 걸릴 수 있습니다. 공백을 포함하되 짧은 설치 경로에서 검증했습니다.
- 프로젝트 소스 변경 시 Unity 컴파일·도메인 리로드는 계속 필요합니다. 이미 Unity에서 실행 중인 임의 C# 코드를 강제 중단하는 기능은 없습니다.
